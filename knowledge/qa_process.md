# QA and artistic-intent approval process

## 2026-10-24 - MGR: operational QA gate and escalation

- **Every VID batch:** run the applicable automated checks on 100% of outputs and perform human review at the asset-tier rates below. Apply the hard invariants and intent-aware checks here; automated metrics and optional VLM output support review but cannot overrule it.
- **Before handoff to ANL:** place a report in `work_directory/qa/<task-or-batch>/` documenting source/candidate identifiers and hashes, method/version, checks and results, sample selection and reviewer, all exceptions/flags, and evidence paths. Mark every candidate pass/fail/hold. Handoff only passed outputs; report unresolved failures or missing evidence to MGR as `BLOCK`.
- **Failure handling:** quarantine failed or uncertain candidates and evidence in `work_directory/qa/`, pause the affected batch, and do not repack or silently waive a failed invariant. MGR resolves the hold; any approved exception must be explicitly scoped and recorded with its approval.
- **Independent QA escalation:** MGR requests a fresh, isolated, read-only agent review before handoff or continuation if output is generative, the model/prompt/scale/color pipeline is new or changed, an automated gate fails, a possible content/layout/color/timing violation or uncertainty is raised, or a critical issue is found in a human sample. The reviewer gets the frozen source/candidate pair, QA rubric and evidence, not generation context or an expected verdict. A dedicated QA agent may be used if configured; otherwise use a fresh `Neverhood_video_champion` instance constrained to QA-only review or another available independent reviewer. Reviewer reports pass/fail/uncertain with cited regions/evidence to MGR. Uncertainty or disagreement keeps the batch on hold. Routine deterministic batches with passed gates need no extra agent beyond the tier-based human review.
- This gate does not waive rights/privacy approval for external asset transfer, user approval for generative method/style, or the existing pilot/bulk authorization rules.

## 2026-10-24 - T8: strict candidate evaluation and sign-off

### Non-negotiable rule
**MAINTAIN ARTISTIC INTENT.** Original assets remain immutable golden references. A candidate is not better merely because it looks sharper or scores well. Reject added/removed objects, silhouette/pose/face/expression changes, changed composition, lighting/mood, palette relationships, clay texture or timing unless the user has approved a clearly scoped exception. No generative candidate enters bulk or production without user method/style approval and separate asset-owner/IP/privacy approval. Automated scores and VLM opinions are gates/support, never final creative authority.

### Stages and approval gates
0. **Rights/data gate (before transfer or model use):** identify exact provider, endpoint, region, plan, model/version, input subset, retention/deletion, training/review use, subprocessors, API costs/rate limits and rights basis. User/project owner explicitly approves external transmission. T8 sent no assets and used no API key.
1. **Golden set:** manager/artist selects and hashes a representative local-only set across palette, lighting, closeups, characters, backgrounds, gradients/dithering, motion/cuts, dark/bright scenes and edge cases. Capture original SMK/indexed frames, palette, timing, crop/registration and reference RGB expansion. Freeze set version; never overwrite originals. Include static and moving clips; T7's repeated still sample is inadequate for temporal tests.
2. **Specification/manifest:** one manifest row per output links source SHA256, archive/id, source dimensions/mode/palette, frame index + PTS/duration/raw/derived rate, target dimensions/aspect, method/model/version/weight hash, prompt/system prompt/reference hashes if permitted, seed (or unsupported), all settings, color assumptions, tool/library versions, output hash, metrics, reviewer, decision, exception and cost. Keep exact prompts and rejection reasons; exclude API secrets.
3. **Offline baseline and blind A/B pilot:** always produce original and local classical baseline. Compare candidate to original, approved target view and baseline at pixel-identical display size; include blink/comparison/contact sheet and full-motion playback. Ask user to approve sample *style and acceptable variation range* before scaling tests. Pilot minimum: at least 20 stills stratified across visual classes plus at least 3 clips with motion, cuts and repeated characters; every pilot result reviewed.
4. **Automated checks (100% of outputs):** verify decode/open, dimensions/scale/aspect/registration, alpha and palette assumptions, valid color tags, no corrupt/duplicate/missing frames, hashes, exact frame count/PTS/duration and unchanged audio/timing. For every candidate upscale, downscale with a fixed documented filter to original dimensions and compare to source (pixel-error/PSNR, SSIM, perceptual/LPIPS, structure/edge, palette/color, luminance/contrast). Also compare candidate at target size against a same-size bicubic-upscaled-source control using SSIM/LPIPS and edge/structure maps; bicubic is a neutral control, not high-resolution ground truth, and deviation from it is not automatically an error. Use change maps/local windows, not just global averages. Compare palette histogram in Lab with Delta E00 ideally (screening script uses approximate Pillow LAB/Delta E76); flag hue and luminance/contrast drift. No metric can prove an invented detail is correct.
5. **Temporal gate for video:** compare adjacent-frame residuals to source cadence after compensation for source motion; measure motion-compensated high-frequency residual/flicker and edge jitter on static/background masks; compare candidate temporal residuals with source and the classical baseline; check scene-cut boundaries, repeated identities, colors and texture. Use scene-cut-aware evaluation, don't interpret intentional stop-motion jumps as faults. Never interpolate by default. Inspect full clip at source and delivery speed. Every flagged scene or character/keyframe sequence is reviewed; outputs from independent generative calls do not inherit consistency approval from a representative still.
6. **Human/VLM gate:** human reviewer records explicit pass/fail against rubric. Optional VLM judge can flag changes using fixed prompt/model/version with source/candidate pairs; it is a *reviewer aid*, not truth and not an automatic pass. If hosted VLM is used, this is another third-party upload and requires the same privacy/rights approval. Reviewer must compare exact registered pair and name suspect regions; opaque numeric scores alone are not sufficient.
7. **Bulk authorization:** user signs off exact method/version, a handful of approved samples and deviation policy; manager authorizes limited batch, spend cap, output target and sample rate. Run small reversible batch, verify regressions, then continue. Do not convert whole archive by default. Every new model/version/prompt/scale/filter/color pipeline restarts at pilot.
8. **Reject/rework/close:** any hard invariant failure, structural invention, new/removed object or mood drift => reject. Log failure class, source/output hashes, method/params and reason; retain rejected candidate only in QA quarantine. One parameter-tuned retry is allowed if it addresses specific defect and is re-evaluated from gate 3; repeated failures escalate to model/method change or source-faithful baseline. At close, archive reports, checksums, metrics, contact sheets, accepted manifest, reject log and explicit signoff; send handoff to analyst only after approval.

### Candidate tiers and human sampling
- **A - hero/foreground/characters/signature backgrounds:** 100% automatic checks AND 100% human frame/image review. For animation also inspect every key pose, cut and transition, and play every clip in full. Never cloud-generate without separate explicit approval.
- **B - important scene assets/non-hero animation:** 100% automatic gates; human review 100% pilot, then minimum 20% stratified random sample plus 100% of flagged frames, cuts and model/version/scene outliers. Human reviewers also watch every short clip; long clips receive scene/character coverage.
- **C - bulk/low-risk repetitive assets:** local deterministic method only unless policy revised; 100% automated gates; human minimum 2% stratified per archive/type/palette/light condition (floor 10 assets or all if <10), plus all flagged/outlier cases. If sample finds one critical issue, pause and inspect affected stratum at 100%; do not simply increase average score.

### Provisional numerical screens (calibrate, do not treat as universal facts)
First run all methods on golden set and accepted human examples; set thresholds before the blind pilot, then lock them. For a **fidelity-preserving** upscale, provisional alerts: candidate downscale-back SSIM <0.98 or PSNR <35 dB; mean Delta E00 >2 or p95 >6; mean luminance shift >2/255, contrast/stddev shift >5%; edge F1 <0.90; palette histogram/structure outlier vs golden distribution. These are trigger thresholds, not permission to alter. This T8 Pillow script estimates global SSIM, PSNR, edge overlap, approximate Lab Delta E76 and luminance; it is not calibrated Delta E00/local SSIM/LPIPS and must not claim standards-grade color difference.

For a generative restoration candidate, these screens can fail because texture was synthesized; that does NOT grant an automatic exception. Use stronger paired human checks and explicit approved deviation map. Downscale-back consistency should remain high for scene composition, geometry and color; any accepted local reconstruction must name the region and uncertainty. A pass on downscale-back alone can hide high-resolution hallucinations. Compare 100% crops, high-frequency residuals, object/edge masks, and, where practical, an independently authored segmentation/object inventory. VLM object detection and diffusion anomaly maps are imperfect; human confirms every new-object flag. No baseline numeric score or generic detector can guarantee absence of hallucinations.

### Fixed VLM reviewer rubric (optional/advisory only)
Use a pinned reviewer model/version, deterministic settings if supported, a frozen prompt and same-sized side-by-side/before-after inputs. Suggested rubric (fixed text): "Compare source and candidate only. Candidate may change sampling resolution but must preserve depicted content, object count/identity, silhouettes/pose/expression, framing/registration, lighting/mood, color relationships, clay texture and (for video) temporal identity/cadence. Do not reward sharpness or infer missing content. List every apparent added/removed/reshaped object and changed region. Score each criterion from 1 to 5; cite region; respond `INSUFFICIENT` if uncertain." Store model/version, prompt hash, inputs and full response. Any suspected structural/content change, score <4, or uncertainty triggers human hold; VLM can never overrule a human fail. Do not send images to a hosted judge without the preflight data-transfer approval.

### Golden regression / thresholds
Keep accepted golden outputs and metric baselines versioned by pipeline. On a change, rerun the full frozen set; compare output hashes (for deterministic local tools), metrics and visual A/B; verify no already-approved asset regresses beyond locked per-class thresholds. For cloud/non-deterministic outputs, hash each result and compare fresh repeats to quantify variance; don't expect exact equality. Any model alias change, API version/terms change, prompt change, random seed support change or output-size change is a new pipeline candidate. Budget limits and request quotas are stop conditions; never auto retry without capped attempt count and cost ceiling.

### Use of `image_qa_metrics.py`
Run from repository root (Pillow required):
`python work_directory/tools/image_qa_metrics.py --original work_directory/extracted/video/c.blb/80/frames/frame_01.png --candidate work_directory/qa/T7_c_blb80/frame_01_lanczos.png --json work_directory/qa/report_metrics.json`
It Lanczos-downscales candidate to original dimensions and reports global PSNR/SSIM, approximate Lab Delta E76 + 32-bin channel histogram TV, luminance mean/std, and thresholded edge overlap. It ran on T7's 320x200 static frame vs all five T7 960x600 scaler outputs; machine-readable JSON is in `work_directory/qa/T8_metrics/`. Example Lanczos result: 43.02 dB PSNR, global SSIM 0.993957, approximate mean Delta E76 1.793, edge F1 0.73977. These reflect a filter resampling loop, not artistic quality or truth. Scores are illustrative only, not approval thresholds; it does not implement LPIPS, Delta E00, local SSIM, temporal flicker, object detection or animation analysis. Document color profile, resize filter, image alignment and threshold before comparing assets.

## 2026-10-24 - T12: Gemini prompt rules (generative upscale)
1. One frame in, one image out; always send the source PNG (never a pre-upscaled or Lanczos version) and request an explicit size via `imageConfig` (`imageSize=4K`, `aspectRatio=4:3`; Gemini 3 image models only, 2.5 flash image is ~1K max).
2. State context (claymation, 1996, palette/dither/compression artefacts) so the model restores rather than restyles.
3. Positive list: clay grain, fingerprints, tool marks, clean edges, remove dithering/blocking.
4. Hard negatives: no added/removed/moved objects, no invented features (teeth, text, screws) in blurred areas, no change to colour/exposure/lighting, no stylisation, no borders/watermark.
5. Prefer "keep soft and simple" over inventing detail where the source is ambiguous.
6. Keep prompts versioned in `tools/scripts/prompts/upscale_vN.txt`; every run saves prompt, model, imageConfig and usage in `*_meta.json`.
7. Post-process: resize to exact target grid (Lanczos), colour-match to source (low-frequency mean/std transfer), then QA: side-by-side 4K crops, alignment-aware low-frequency PSNR (`work_directory/tools/uhd_compare.py`), human sign-off. Do not use full-reference PSNR/SSIM alone (see T11).
8. Temporal: test 3-5 consecutive frames before any video batch; reject on flicker or detail that changes between frames.
9. API key only via environment (`GEMINI_API_KEY`), never stored in repo.

## 2026-10-24 - T15: intent-aware scoring (supersedes full-reference ranking)
- Added fine detail that is consistent with the material and the artistic intent (clay fingerprints, tool marks, grain, cracks, surface relief) is NOT an error and must not be penalised.
- Automatic part = gates only: G1 layout (band-limited, colour-matched SSIM >= 0.95), G2 colour (block-mean Lab dE mean <= 6, channel shift <= 8). See `work_directory/tools/uhd_qa_v2.py` (provisional thresholds).
- Ranking among gate-passers = visual detail rubric 0-3 on 4K crops, then colour drift. Penalise only intent violations: unsupported new objects/features, changed pose/expression, stylisation (plastic/airbrushed/painterly), recolouring, relit scenes.
- Do not use PSNR/SSIM/edge-F1 vs the low-res source to rank generative output; no automatic detail metric was found that separates real texture from scaler artefacts.
- Check "invented" claims against the source pixels before reporting them (teeth in frame_000 are supported by the source).
- Sizes: 4:3 source -> 2880x2160 master (9x), 3840x2160 pillarbox; crop (never squeeze) generative outputs to exact 4:3.
