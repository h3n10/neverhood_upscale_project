# Upscaling and restoration

## 2026-10-23 - T7: candidate methods, clay-art fit, and local test

### Artistic rule and recommended baseline
**MAINTAIN ARTISTIC INTENT.** Preserve frame timing, composition, lighting, palette colors and tactile clay texture. Keep the original SMK and decoded palette/index frames as immutable references. No AI/generative edit or production substitution without manager approval. Do not denoise, deband, de-dither or recolor unless an identified defect warrants a restrained A/B test; these can erase intentional clay texture and palette stepping.

Use a modest classical resize as the reproducible baseline. For organic clay contours compare Lanczos (smooth, can create intermediate colors/ringing) with nearest (exact source samples, blocky); retain whichever is most faithful at viewing size. xBR/HQx/EPX are edge/pixel-art filters and visibly regularize contours; they are not assumed suitable for textured clay. Preserve source palette and PNG/index masters; an RGB derivative must record color interpretation and filter. Targets are scale-agnostic: calculate exact aspect-preserving size from each source; keep 4:3 pillarboxed on 16:9 rather than crop/stretch. ScummVM's 640x480 logical canvas remains fixed, so these are reference/upscaled assets, not drop-in HD BLB replacements.

### Tiny QA comparison (not a general quality verdict)
Ran `work_directory/tools/compare_classical_scalers.py` on the two extracted 320x200 paletted PNG frames from `c.blb#80`, creating 3x 960x600 PNGs for nearest, Lanczos, HQx, xBR and EPX plus contact sheets in `work_directory/qa/T7_c_blb80/`. Both inputs are byte-identical (same SHA-256); all methods produced identical corresponding outputs for both, so temporal consistency is trivially exact for this static 3-frame clip. Visual side-by-side: nearest retains source blocks; Lanczos is a modestly smoother candidate; HQx/xBR introduce stronger edge stylization; EPX is block-oriented. No method can be chosen conclusively from this static, small test; compare motion and full-size details on a representative non-static clay clip before production. Commands are reproducible via the script; no AI tools installed and no source/final game assets modified.

### Candidate methods and installability here
- **Classical (available now):** FFmpeg has `scale` (nearest/bilinear/bicubic/Lanczos), `hqx` 2x/3x/4x, `xbr` 2x/3x/4x, `epx` and `super2xsai`; Pillow is installed for image QA. Lanczos/nearest are first choices to compare; treat edge-aware pixel-art scalers as a control. `scale2x` is a family/algorithm name, not confirmed as a named FFmpeg filter in this build (EPX is the available related scaler).
- **Real-ESRGAN / ESRGAN variants:** learned natural-image restoration/super-resolution; GAN variants may invent texture, sharpen/reshape clay details and shift color. The upstream GitHub latest release has no binary assets; Python/weights/runtime installation would be nontrivial here. Compare conservative/non-GAN options first, if later authorized.
- **waifu2x-ncnn-vulkan:** compact Windows release exists (about 34 MB downloaded archive at research time, plus model/runtime needs); removes noise and upscales, but anime-trained priors risk flattening or outlining clay. Potentially installable, not verified: machine is Intel UHD Graphics 620 (reported 1 GB adapter memory), no NVIDIA GPU; Vulkan support and usable memory/performance were not verified. Not installed.
- **SwinIR:** published x2/x3/x4 weights commonly tens of MB (example classical x4 65 MB, real-SR GAN x4 136 MB at research time), but Python/PyTorch and dependencies are not present. Natural-image restoration prior can alter textures; implementation/weights are not installed.
- **Video2X:** orchestration for external upscalers/interpolators, not a model/quality guarantee. Latest Windows archives checked were about 188-217 MB before any additional models; installable in principle, not installed. **Upscayl** (Real-ESRGAN GUI; Windows installer ~249 MB) and **chaiNNer** (~150 MB Windows installer) likewise add substantial packages/models; not installed. Do not assume a GUI fixes model/hardware or temporal consistency.
- **RIFE / interpolation apps:** separate synthesis stage (see `video_conversion.md`); RIFE NCNN Windows release checked ~412 MB. Not installed; hallucinated in-betweens are particularly risky for stop motion.
- **Diffusion/LLM restoration:** can invent, remove or reinterpret scene detail and introduce frame-to-frame drift. Defer entirely unless the manager authorizes a specifically scoped experiment; never use as default restoration.

Package sizes are approximate GitHub release downloads checked for T7, not total installed footprint; update before install. No heavy tool/model was downloaded. Machine inventory is not a benchmark: FFmpeg 2026-10-22 build is local; Python Pillow exists, while PyTorch, NumPy, OpenCV and scikit-image are absent. FFmpeg includes `zscale`, `libplacebo`, `libvmaf`, x265 and common filters; GPU filter/hardware acceleration was not benchmarked.

### QA plan
1. Decode with frame passthrough; save original SMK, decoded indexed/RGB PNGs, palette bytes and exact timing metadata. Preserve full-frame originals; never feed color-managed output back as if it were an original index plane.
2. Compare nearest, Lanczos and one edge-aware control at exact 3x/4x; no crops or geometry changes. Inspect 100% crops, contact sheets, color/edge halos and side-by-side/flicker through moving frames. Include source and method, command/options, source+output checksums, palette, dimensions, rate, frame count, and color tags in manifest.
3. Use lossless intermediate first; verify frame count, per-frame duration/PTS, unchanged frames, decoded palette colors and output metadata. When an HR ground truth does not exist, PSNR/SSIM/LPIPS/VMAF cannot establish recovered truth: metrics are supporting checks only. No numeric metric was run for the T7 still-scaler comparison.
4. If de-noise/deband is actually needed, compare no-filter against very low-strength `hqdn3d` / `deband`; reject texture loss, color/palette changes or flicker. De-dithering is not a recovery of unknown source colors. Check palette-expanded output against original RGB lookup before any enhancement.
5. Interpolation is off by default. Preserve original SMK frame rate and holds; test a doubled-rate RIFE sidecar only if explicitly requested, with original+generated frame labels, cadence/duration check and temporal artifact review. Never replace native timing based on smoothness preference alone.
